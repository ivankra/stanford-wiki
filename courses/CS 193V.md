# CS 193V: Effective Vibecoding

A new course for non-CS students to help build software using AI-assisted coding tools, without having to read or write any code. Teaches the surrounding craft: version control, testing, deployment, and the security holes AI-written code tends to leave. CS majors (and anyone who can code) are advised to take [CS 146S](CS%20146S.md) instead.

## Materials

The course writes everything down in public — syllabus, a deck and a page per lecture, each assignment in full — and it doesn't record, by its own statement, so an outside reader misses nothing an enrolled student gets outside the room. The exception is the starter files: from assignment 2 on they come from a per-student repository in a GitHub organization that admits stanford.edu addresses only. The environment the work runs in, unusually, installs for anyone.

- **Syllabus**: the [syllabus](https://web.stanford.edu/class/archive/cs/cs193v/cs193v.1272/syllabus) gives the 10-week topic list, who should take [CS 146S](CS%20146S.md) instead, the grading formula (homework 20%, tutorial 40%, project 40%) and a hard no-late-work rule, since every assignment is shown to a group of 4 at the start of the next lecture. There is no dated schedule.
- **Slides**: a `Lecture Slides.pdf` beside each published lecture page — [Introduction](https://web.stanford.edu/class/archive/cs/cs193v/cs193v.1272/lectures/00/Lecture%20Slides.pdf), [Using the Terminal](https://web.stanford.edu/class/archive/cs/cs193v/cs193v.1272/lectures/01/Lecture%20Slides.pdf) and [Source Control](https://web.stanford.edu/class/archive/cs/cs193v/cs193v.1272/lectures/02/Lecture%20Slides.pdf) — with the rest to come.
- **Notes**: the lecture pages themselves, plus the [development-environment guide](https://web.stanford.edu/class/archive/cs/cs193v/cs193v.1272/cs193v-dev/): an install page each for macOS, Windows and Linux, and a troubleshooting guide.
- **Videos**: none. "Lectures are not recorded this quarter and you will need to attend in person."
- **Assignments**: [assignment 0](https://web.stanford.edu/class/archive/cs/cs193v/cs193v.1272/assignments/a0/) registers for the tool licenses and GitHub, [assignment 1](https://web.stanford.edu/class/archive/cs/cs193v/cs193v.1272/assignments/a1/) installs the environment, and [assignment 2](https://web.stanford.edu/class/archive/cs/cs193v/cs193v.1272/assignments/a2/) is the first real build, an image-transforming website. From there each one starts by cloning `cs193v-students/a<n>-<sunet>`, which an outside reader can't reach: that organization has no public repositories and invites stanford.edu addresses only.
- **Solutions**: none, and none to expect; the work is open-ended and graded on completion.
- **Exams**: none; the grade is homework, tutorial participation and the project.
- **Projects**: a team project from the end of week 7, details still to be announced, and no past work to look at in a first offering.
- **Repo**: the course's [container](https://github.com/cs193v/cs193v-container) is public, along with a git-games demo it uses for the source-control lecture.
- **Self-study**: the [development environment](https://web.stanford.edu/class/archive/cs/cs193v/cs193v.1272/cs193v-dev/) is the course's answer to running coding agents safely, a Podman sandbox that keeps the agent away from the rest of your files. Its [installer](https://web.stanford.edu/class/cs193v/cs193v-dev/files/install-cs193v.sh) is a public script that installs podman, ssh and uidmap and never asks who you are.

## Syllabus

From the [published breakdown](https://web.stanford.edu/class/archive/cs/cs193v/cs193v.1272/syllabus):

1. **Weeks 1–2, technical foundations**: the command line, git and GitHub, software testing.
2. **Week 3, asking for what you want**: plan mode, iterating on designs, and the basics of user interviews.
3. **Week 4**: data formats, data analysis and visualization, API keys and how to keep them safe.
4. **Weeks 5–6, web applications**: ports, IP addresses and DNS, the client/server model, deployment, style and iteration.
5. **Week 7, working in a team**: issue tracking, pull requests, continuous integration.
6. **Week 8, privacy and security**: containers and virtual machines, zero-days, "the 'Lethal Trifecta'".
7. **Week 9**: mobile development — getting code onto a device, testing and debugging there.

The stated ceiling is part of the argument: current tools "aren't good enough to build large-scale programs autonomously", and AI-written code "frequently contains critical security or privacy holes", which week 8 examines firsthand.
