# CS 340R: Rusty Systems

A seminar with a thesis: forty years of C made asynchrony, memory management and array indexing look like *systems* problems rather than *C* problems, and Rust's different constraints should therefore open different research questions. The method is empirical — three weeks learning Rust, then seven reimplementing a published non-Rust system in it, reading the Rust systems literature alongside and noting what got easier and what got much harder.

## Syllabus

[Twenty sessions](https://web.stanford.edu/class/cs340r/) from April 2.

1. Learning Rust (Apr 2-18): the Rust Book cover to cover over five weeks of assigned chapters, read against systems papers — "System Programming in Rust: Beyond Safety", kernel extension verification, Tock's "Ownership is Theft", the case for writing a kernel in Rust.
2. What goes wrong (Apr 23-30): how programmers actually use `unsafe`, memory and thread safety issues in real-world Rust, Rudra's ecosystem-scale bug hunt.
3. Systems built in Rust (May 2-30): multiprogramming a 64kB computer, shrinking embedded binaries, RedLeaf, Theseus, modular information flow through ownership, Splinter, Servo, Cornflakes, NetBricks — several with their authors as guests.
4. Jun 4 wrap-up and reflections; project reports due Jun 11.
