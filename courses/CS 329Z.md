# CS 329Z: Engineering AI Agents

How to engineer agentic systems, from simple LLM pipelines to compound AI systems to autonomous agents. Students build RAG, tool use and agent loops from scratch before seeing how frameworks like DSPy abstract them, then turn to optimization, data, evaluation and safety. The work centers on a quarter-long team project judged mainly on how rigorously the agent is evaluated.

## Materials

The site says so itself: "All course materials on this site are publicly available", and it holds. The schedule, the roughly 50 readings, the decks as they are released and the whole project spec open without an account. The gap is the recordings, which cameras capture and Canvas keeps, with no public copy under this code or the instructors' names.

- **Syllabus**: the [course site](https://cs329z.stanford.edu/) is the dated schedule, each lecture with a paragraph of scope and its readings; [logistics](https://cs329z.stanford.edu/logistics.html) carries the grading split (project 40%, homework 15%, quizzes 15%, paper video 10%, peer review 20%), the prerequisites and an AI policy that treats models as "collaborators you think alongside" while barring finished answers.
- **Slides**: a Google Drive deck per lecture held — [agentic systems and the compound-AI spectrum](https://drive.google.com/file/d/1Wlf723d9-LBuTp56QYppaZwozOAetTsC/view?usp=drive_link), [LLM internals for builders](https://drive.google.com/file/d/1kekt_p0n-_Q4Y2dKYEkH87NEx6mr8nRE/view?usp=drive_link) and [retrieval-augmented generation](https://drive.google.com/file/d/1q6HIZHlfIKgV8GOXubSdz1EkDukOm7pE/view?usp=share_link) — each downloading without a Google account.
- **Notes**: none written; the reading list does that work, with the course's papers and engineering posts linked lecture by lecture.
- **Videos**: Canvas only. The logistics page says cameras at the back record the instructor and students reach the files by logging in.
- **Assignments**: the [project spec](https://cs329z.stanford.edu/project.html) is public and detailed — what counts as a project, the ICLR submission format for all 3 reports, an AI-use disclosure at every stage, and the demand that teams define their evaluation early rather than demo one working instance. HW1, an agent harness over a corporate email archive built without frameworks, and HW2, an evaluation suite for a pre-built agent, are described but not yet released.
- **Solutions**: none published; the honor code asks students not to look up existing implementations.
- **Exams**: 2 oral quizzes of 10 minutes, after each homework, where students explain their design decisions. Nothing is published.
- **Projects**: team demos and a 10-minute paper video from each student, with 4 rounds of peer review. This is the first offering, so there is no archive yet.
- **Repo**: none. HW1 is deliberately built "with no agent frameworks: just a chat-completion call and code you write yourself", so no starter code is handed out.

## Syllabus

Two lectures a week in ten blocks, plus two guest lectures (TBA):

1. Foundations: what agentic systems are; LLMs for builders (structured I/O, decoding, context engineering, cost and latency)
2. Building blocks: RAG and tool use/MCP, each built from scratch
3. Frameworks and agent design: DSPy, LangGraph, LlamaIndex; workflow and agent patterns (ReAct, plan-and-execute, reflection)
4. Memory and multi-agent systems
5. Optimization: prompt optimization (GEPA, MIPROv2), test-time compute, LoRA, distillation, RLHF/DPO
6. Data: traces and feedback, data flywheels, synthetic data, data selection
7. Evaluation: benchmark design with a request/environment/stopping-criteria/scorer framework, LLM-as-judge, pass@k vs. pass^k
8. Safety: prompt injection, privacy, sandboxing, guardrails
9. Coding agents (SWE-agent, OpenHands, SWE-bench) and proactive agents
10. Frontiers: web and computer-use agents, observability, open problems; final demo day in finals week
