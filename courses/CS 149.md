# CS 149: Parallel Computing

The course's premise is that you cannot write fast parallel code without knowing the machine: "Because writing good parallel programs requires an understanding of key machine performance characteristics, this course will cover both parallel hardware and software design." Hardware ranges from phones to supercomputers, and the assignments are substantial.

## Syllabus

From the [schedule](https://gfxcourses.stanford.edu/cs149/fall25):

1. **Why parallelism, why efficiency** — the challenges of parallelizing code and the motivations for parallel chips.
2. **A modern multi-core processor**, in two parts — multi-core, SIMD and multi-threading, then latency versus bandwidth, with ISPC as the programming abstraction and a discussion of abstraction versus implementation.
3. **Parallelizing code: an example thought process** — the same program in data-parallel and shared-address-space models.
4. **Program optimization** — work distribution and scheduling, then locality.
5. **The rest of the quarter** covers synchronization and memory consistency, GPU architecture, and the programming models the catalog lists: threads, data parallel and streaming, MapReduce, Apache Spark, SPMD, message passing, SIMT, transactions and nested parallelism.
