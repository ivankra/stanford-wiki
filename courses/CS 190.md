# CS 190: Software Design Studio

A studio, not a lecture course: most meetings are discussion and code review of the students' own systems, iterated through "implementation, review, and revision". Enrollment is capped and by application, and it has run every Winter since 2020.

## Materials

Everything the course hands an enrolled student is on the open site — the meeting list, the course-information page, the 3 project specifications in full — and so are the Winter 2022 and Winter 2023 offerings. What it doesn't hand anyone is decks for the review sessions, solutions or starter code, because there aren't any.

- **Syllabus**: the dated [class-meeting list](https://web.stanford.edu/~ouster/cs190-winter24/all_lectures/), plus a [course-information page](https://web.stanford.edu/~ouster/cs190-winter24/info/) with the 18-student cap, the 15-to-20-hours-a-week workload estimate, the grading approach and the late-day rule.
- **Slides**: 4 decks as both pptx and pdf — [Raft](https://web.stanford.edu/~ouster/cs190-winter24/slides/raft.pdf), the *Philosophy of Software Design* discussion, the first Raft review and the wrap-up — against 15 meetings. The rest are code review and discussion, with nothing to post.
- **Notes**: a page per session with its reading — the extended Raft paper, a students' guide to Raft, Protocol Buffers documentation, Rob Pike on simplicity, grugbrain.dev.
- **Videos**: no page mentions recording, in any offering.
- **Assignments**: all 3 [project specifications](https://web.stanford.edu/~ouster/cs190-winter24/all_projects/), written down to the features required and the libraries forbidden: Raft leader election with a remote shell, Raft log replication revised from code review, and a simplified `make`.
- **Solutions**, **Repo**: none of either. The projects are open-ended and graded on design quality, and project 1 bars existing networking libraries — students build on the socket calls directly, from scratch.
- **Exams**: none. "There will be no exams in this class."
- **Projects**: students' code is reviewed in class and in individual meetings, and none of it is published.
- **Textbook**: *A Philosophy of Software Design*, 2nd edition, which the course is built on and which is bought, not free: "I will not go over the material of the book in detail in lecture, but the material is essential for the class."

## Syllabus

From the [course description](https://web.stanford.edu/~ouster/cs190-winter24/): "how to decompose large complex systems into classes that can be implemented and maintained easily. Topics include information hiding, deep classes, API design, managing complexity, error handling, and how to write in-code documentation."

The [meeting list](https://web.stanford.edu/~ouster/cs190-winter24/all_lectures) opens with an introduction and the Raft consensus algorithm in week 1, then alternates design topics with review sessions across the quarter. "The class involves significant system software implementation and uses an iterative approach consisting of implementation, review, and revision."
