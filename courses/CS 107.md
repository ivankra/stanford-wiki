# CS 107: Computer Organization and Systems

The course that takes the floor out from under [CS 106B](CS%20106B.md): C instead of C++, bits and bytes instead of collections, and by the end a heap allocator of your own and enough x86-64 to read what the compiler produced.

## Syllabus

The [calendar](https://web.stanford.edu/class/archive/cs/cs107/cs107.1272/calendar) hangs the quarter on five questions:

1. **How can a computer represent integers?** — binary and hex, `char`/`short`/`int`/`long`, two's complement, overflow, bitwise and shift operators.
2. **How can it represent text?** — C strings, `string.h`, null termination, buffer overflows and the security consequences.
3. **How do we manage memory?** — pointers and arrays, the stack and the heap, `malloc`, use-after-free.
4. **How do we write code for any type?** — `void *` generics and function pointers, `qsort` and friends.
5. **How does a computer execute C?** — x86-64 data movement, ALU operations, condition codes, control flow and the runtime stack; then writing a heap allocator, optimization, and caching and memory hierarchies.

Five assignments (assign0–assign4), a weekly lab, most weeks a lecture quiz, a midterm and a final.
