# CS 350: Secure Compilation

A compiler that preserves the meaning of a program need not preserve its security: an attacker at the target level has powers the source language ruled out. This course, at the join of programming languages and security, asks what criterion a compiler should meet instead, what architecture support makes the criterion achievable, and how to prove the result — mostly by backtranslation, constructing a source-level attacker from a target-level one.

## Syllabus

From the catalog description, which is identical in both offerings; no public syllabus.

1. Threat models for secure compilers.
2. Formal criteria a secure compiler should adhere to.
3. The security relevance of those criteria — what each one actually buys.
4. Security architectures employed to achieve secure compilation.
5. Proof techniques for secure compilation, with a focus on backtranslation.
