# CS 356: Topics in Computer and Network Security

A discussion seminar: each class covers 1–2 formative security papers, each student presents one recent paper, and small groups write an original research paper. In-person attendance is required, and there is no final exam.

## Materials

The whole course is one public page: a schedule that links every required paper, and requirements for the reading responses, the topic presentation and the quarter-long research project spelled out down to the page limits. What a seminar produces in the room — the presentations, the discussion, the projects — is not published.

- **Syllabus**: the [site](https://cs356.stanford.edu/), with the dated schedule, every paper linked, and the grading split: readings and discussion 30%, topic presentation 15%, course project 55% across a proposal, a progress report, a class presentation and a final paper.
- **Slides**: none posted; each class is a discussion and the student topic presentations stay in the room.
- **Notes**: none; the assigned papers are the reading, and the schedule links each one.
- **Videos**: attendance is required in person, and the site says nothing about recording.
- **Assignments**: the requirements are on the same page, including what a reading response must do and how long a presentation runs. Submissions go through Gradescope and discussion through Ed.
- **Solutions**, **Exams**, **Repo**: none. The written work is responses and a research paper, there is no exam, and the course distributes no code.
- **Projects**: the group research paper is 55% of the grade, and the site says that "in past offerings, well-executed projects have led to publications", but no offering posts them.
- **Older offerings**: the site is rewritten in place each year, so Autumn 2020 through [Autumn 2025](https://web.archive.org/web/20260213130303/https://cs356.stanford.edu/) survive only as Internet Archive snapshots, each with that year's paper list.

## Syllabus

1–2 papers per class, mostly formative work in each area:

1. Introduction: security nihilism, weak keys in network devices, how to read a paper
2. Web privacy and tracking; usability (browser warnings, AI coding assistants)
3. Authentication and phishing; spam and eCrime
4. System attacks and defenses (blind ROP, data-only attacks, WebAssembly, adaptive attacks on LLM defenses)
5. IoT botnets (Mirai); network security (Diffie-Hellman, satellite links)
6. Cyber-physical systems (cars, grid malware); hardware (Rowhammer, Spectre)
7. At-risk populations (intimate-partner spyware, state hacking); censorship
8. AI-enabled attacks and abuse (deepfake markets, Glaze); data leakage (de-anonymization, LLM training-data extraction)
9. Problem selection; final project presentations

## Prerequisites

None official. The catalog strongly encourages [CS 155](CS%20155.md) first; the site expects it or equivalent, plus a mature understanding of software systems and networks.
